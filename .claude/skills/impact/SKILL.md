# 변경 영향도 분석

## 원칙
- 코드를 고치지 않는다. 파일을 만들거나 수정 · 삭제하지 않고 답변으로만 보고한다.
- 모든 항목에 근거 `파일:줄번호` 를 단다. 인용 전에 그 줄을 다시 열어 확인한다. 근거를 못 대면 "미확인"으로 둔다.
- 검색으로 찾지 못하는 경로가 의심되면 추측으로 메우지 않고 "추적 한계"에 따로 적는다.
- 탐색 범위는 저장소 전체(`legacy/` · `modern/` · `db/` 등)다. `node_modules` · `vendor` · `build` · `dist` 는 대상 함수를 직접 부를 때만 본다.

## 1. 대상 정하기
- `$ARGUMENTS` 가 `파일:줄번호` 면 그 줄을 감싸는 함수 · 메서드 · 프로시저를 대상으로 한다.
- 이름이면 정의를 검색한다(PHP `function 이름`, Java 메서드 선언, SQL `CREATE PROCEDURE 이름`, TS `function 이름` · `const 이름 =`).
  - 같은 이름의 정의가 여러 개면(오버로드 · 다른 클래스 · 다른 모듈) 후보를 `파일:줄번호` 로 나열하고 어느 것인지 묻는다.
  - 정의를 못 찾으면 멈추고 알린다.
- `$ARGUMENTS` 가 비어 있으면 대상을 묻는다.
- 대상의 시그니처(인자 · 반환 · 부수 효과)를 한 줄로 요약해 둔다.

## 2. 호출부 역추적
- 직접 호출 → 그 호출부를 감싸는 함수를 부르는 곳 → … 을 **진입점**에 닿을 때까지 반복한다.
  - 진입점: 화면(PHP 페이지, Thymeleaf 템플릿, React 컴포넌트), URL 매핑(`@GetMapping` 등, 클래스 레벨 `@RequestMapping` 과 합친 전체 경로),
    스케줄러 · 배치, DB 에서 직접 부르는 프로시저 · 트리거.
- 단계마다 호출문 줄을 근거로 단다. 이름이 같은 다른 함수의 호출을 섞지 않도록 수신 객체 타입 · include 관계로 확인한다.
- URL 진입점은 그 URL 을 부르는 쪽까지 이어 본다: 템플릿의 `href` · `th:action` · `form action`, `redirect:` 문자열, `modern/web` 의 API 함수 → 훅 → 컴포넌트.
- 같은 경로가 여러 번 나오면 한 번만 적고, 순환 호출은 표시하고 멈춘다.
- 깊이가 6단계를 넘거나 진입점이 10개를 넘으면 중간 결과를 보여 주고 계속할지 묻는다.

## 3. 테이블 영향
- 대상 함수(와 대상이 부르는 하위 함수 · 프로시저)가 **읽는** 테이블과 **쓰는** 테이블(INSERT · UPDATE · DELETE · MERGE)을 구분해 모은다.
  근거는 SQL 문 · JPA 엔티티 `@Table` · 리포지토리 메서드 · `EXEC` 호출 줄이다. 뷰를 쓰면 뷰 정의에서 원본 테이블까지 따라간다.
- 그 테이블을 쓰는 **다른** 함수를 찾는다. 특히:
  - 대상이 쓰는 테이블을 읽는 함수 → 대상 변경으로 결과가 달라질 수 있다.
  - 대상이 읽는 테이블에 쓰는 함수 → 대상의 전제(상태 코드 · NULL 여부 등)를 바꿀 수 있다.
- 스키마 파일에서 해당 테이블의 제약 · 트리거 · 콜레이션을 확인해 근거로 붙인다.

## 4. 비즈니스 규칙 연결
- 대상이 속한 모듈의 `docs/<모듈명>/BUSINESS-RULES.md` 가 있으면 읽는다.
  - `legacy/item-bank-php` · 이관된 `item` 도메인 → `item-bank` / `legacy/assignment-thymeleaf` · `assignment` 도메인 → `assignment` /
    `legacy/grade-mssql` → `grade`
- 규칙의 **근거** 줄이 대상 함수 · 호출 경로 · 같은 테이블 함수 안에 있으면 그 규칙 ID(`BR-xx`)를 연결한다. 이름이 비슷하다는 이유만으로 연결하지 않는다.
- 문서가 없으면 "BUSINESS-RULES.md 없음"이라고 적고 넘어간다(새로 만들지 않는다).

## 5. 추적 한계 점검
검색 결과가 비었다고 "호출부 없음"으로 단정하지 말고 아래를 확인한다. 해당하면 "추적 한계"에 적는다.
- PHP: 가변 함수 `$fn()` · `call_user_func` · 변수로 만든 `include` 경로, 문자열로 조립한 URL · 폼 action
- Java: 리플렉션, `ApplicationContext.getBean`, AOP · 이벤트 리스너, 인터페이스를 거친 호출(구현체가 여럿이면 전부 나열)
- SQL: 동적 SQL(`sp_executesql` · `EXEC(@sql)`), 문자열로 조립한 테이블 · 컬럼명, 트리거, 다른 DB · 외부 배치에서의 호출
- 웹: 템플릿 문자열로 만든 API 경로, 설정 · DB 값으로 결정되는 라우트
- 저장소 밖(다른 서비스 · 수동 운영 스크립트 · 크론)에서 부를 가능성

## 6. 출력 형식 (순서 고정)

### 대상
`파일:줄번호` — 시그니처 한 줄 요약

### 영향받는 화면 · 진입점
| 화면 · URL | 종류 | 근거 |
|---|---|---|
| `GET /search.php` | PHP 페이지 | `legacy/item-bank-php/search.php:12` |

### 호출 경로
```
[진입점] GET /search.php (search.php:12)
  → buildQuery() (search.php:210)
    → 대상함수() (search.php:522)
```
- 경로마다 한 블록. 각 단계에 `파일:줄번호`.

### 영향받는 테이블
| 테이블 | 대상의 사용(읽기 / 쓰기) | 같은 테이블을 쓰는 다른 함수 | 근거 |
|---|---|---|---|

### 관련 규칙 ID
| 규칙 ID | 규칙 이름 | 연결 이유 | 근거 |
|---|---|---|---|

### 수정 전에 확보해야 할 테스트 케이스
| # | 검증할 동작 | 입력 · 전제 데이터 | 기대 결과 | 관련 경로 · 규칙 | 기존 테스트 |
|---|---|---|---|---|---|
- 진입점마다 최소 1개, 연결된 규칙마다 최소 1개, 같은 테이블을 쓰는 다른 함수와의 상호작용 1개 이상.
- 경계값 · 예외 가지(빈 값, NULL, 상태 코드 등)를 포함한다.
- 이미 있는 테스트(`characterization/`, `*Test.java`, `*.test.tsx`)가 그 동작을 덮으면 `파일:줄번호` 를, 없으면 "없음"을 적는다.

### 추적 한계
- 의심 지점, 왜 검색으로 확정할 수 없는지, 사람이 확인할 방법을 한 줄씩. 없으면 "없음".
