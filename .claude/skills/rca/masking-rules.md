# RCA 리포트 마스킹 규칙

리포트(`docs/rca/<시나리오>.md`)를 저장하기 전에 아래 규칙을 모두 적용한다. 원본 로그는 고치지 않고, 리포트에 옮기는 값만 가린다.

| 대상 | 예 (원본 형태) | 리포트 표기 |
|---|---|---|
| IP — 구분이 필요 없음 | `10.20.6.87` | `<IP>` |
| IP — 구분이 필요함 | 서버 · upstream · 반복 조회 client | 역할 별칭: `API-1`, `API-2`, `DB-1`, `교사단말A`, `교사단말B` … |
| 이메일 | `name@example.com` | `<EMAIL>` |
| 학생 식별자 | `STU-12345` | `STU-****` |
| 토큰 | `Bearer eyJ…`, `token=…`, 세션 · API 키 | `Bearer <TOKEN>`, `token=<TOKEN>` |
| 비밀번호 | `password=…`, 접속 문자열의 비밀번호 | `password=<REDACTED>` |

## 역할 별칭

- 가설 · 타임라인에서 서로 다른 호스트를 구분해야 할 때만 별칭을 쓴다(예: 두 upstream, 같은 client 의 반복 조회와 다른 client).
- 별칭은 역할 + 순번으로 짓는다: 애플리케이션 서버 `API-1 · API-2`, DB `DB-1`, nginx `LB-1`, 사용자 단말 `교사단말A · 교사단말B …`.
- 한 리포트 안에서 같은 값은 끝까지 같은 별칭을 쓴다. 대응은 작성 중에만 머릿속(대화)에서 유지하고 파일로 남기지 않는다.
- 별칭이 처음 나오는 곳에 역할을 한 번 설명한다(예: "`API-2`(upstream 그룹의 두 번째 서버)").

## 적용 범위

- 본문 서술, 표, 원문 발췌, 코드 블록, 예시 명령 모두에 적용한다. 예시 명령의 `grep '<IP>'` 처럼 값이 필요한 자리도 별칭이나 자리표시자로 쓴다.
- 이메일 · 학생 식별자 · 토큰이 들어 있는 줄은 되도록 발췌하지 않고 `파일:줄번호` 만 적는다.
- 도메인 이름(`lms.example.com` 등)과 커넥션 객체 해시(`@6e8f14d3`)는 개인 · 비밀 정보가 아니므로 그대로 둔다.

## 저장 후 점검

아래 명령의 결과가 모두 0건이어야 한다.

```bash
R=docs/rca/<시나리오>.md
grep -nE '([0-9]{1,3}\.){3}[0-9]{1,3}' "$R"
grep -nE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' "$R"
grep -nE 'STU-[0-9]+' "$R"
grep -niE '(bearer|token|password|passwd|secret|api[_-]?key)[=: ]+[^<[:space:]]' "$R"
```
